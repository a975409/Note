這個錯誤（**錯誤代碼：15023**）是 SQL Server 中非常經典的**「孤兒使用者」（Orphaned User）**問題。

### 為什麼會發生這個錯誤？
當你將資料庫還原（Restore）或附加（Attach）到新的 SQL Server 執行個體（Instance）時，資料庫內部已經記錄了使用者 `hyjr`（這稱為**資料庫使用者**）。

然而，新伺服器上的**系統登入帳號**（Login，即你在「安全性」->「登入名」中看到的 `hyjr`）與該資料庫內部的「資料庫使用者」之間的 **SID（安全性識別碼）不一致**。即使兩者名字一模一樣，系統也會認為他們是不同的帳號，因此當你嘗試在資料庫中新建或對應此使用者時，系統就會報錯，提示該使用者已存在。

---

### 解決方法

你不需要刪除該使用者，只需要將**伺服器登入名**與**資料庫使用者**重新關聯（對應）即可。請依照以下步驟操作：

#### 步驟 1：開啟新查詢視窗
在 SQL Server Management Studio (SSMS) 中，點擊上方工具列的 **「新增查詢」 (New Query)**。

#### 步驟 2：確認切換到該資料庫
在查詢視窗中，先切換到你發生錯誤的那個資料庫（請將 `[你的資料庫名稱]` 替換為實際的資料庫名稱）：
```sql
USE [你的資料庫名稱];
GO
```

#### 步驟 3：修復關聯（推薦使用 SQL Server 2016 及更新版本的方法）
請執行以下 T-SQL 指令，將現有的資料庫使用者 `hyjr` 重新對應到伺服器登入名 `hyjr`：

```sql
ALTER USER [hyjr] WITH LOGIN = [hyjr];
GO
```

執行完畢後，你就會發現 `hyjr` 已經成功與該資料庫關聯，且可以正常存取，不會再跳出 15023 的錯誤了！


環境變數是**作業系統層級的概念**,ASP.NET Core 啟動時,會讀取該處理序(process)取得的**所有環境變數**。專案內的 `launchSettings.json` 只是其中一種來源。

## 環境變數的來源

| 來源 | 範圍 | 說明 |
|---|---|---|
| `launchSettings.json` | 僅本機開發 | 由 Visual Studio、`dotnet run` 讀取後,**注入**到程式處理序 |
| VS 偵錯屬性 | 僅本機開發 | 實際上也是寫入 `launchSettings.json` |
| 使用者層級環境變數 | 該 Windows 使用者 | 系統內容 → 環境變數 |
| 系統層級環境變數 | 整台主機 | 所有應用程式都能讀到 |
| IIS `web.config` 的 `<environmentVariables>` | 僅該網站 | 由 ASP.NET Core Module 注入 |
| IIS 應用程式集區的環境變數 | 該集區 | 用 `appcmd` 或 IIS 設定 |
| Docker / K8s / 雲端服務設定 | 該容器或服務 | 例如 Azure App Service 的應用程式設定 |

這些來源在程式啟動後,對 ASP.NET Core 來說**都是環境變數**,透過 `AddEnvironmentVariables()` 載入。

## 對先前問題的影響

1. **開發時**:`launchSettings.json`、系統環境變數、使用者環境變數,只要名稱相同,都會覆蓋 User Secrets。
2. **上線後**:User Secrets 通常不載入,所以由主機、IIS 或 `web.config` 的環境變數提供值。
3. **同名環境變數有多個來源時**(例如系統層級與 `launchSettings.json`):`launchSettings.json` 是在啟動處理序時才注入,通常會覆蓋同名的系統環境變數,最終以處理序中實際取得的值為準。

## 實務提醒

- 修改系統環境變數後,**需要重新啟動** Visual Studio、終端機或 IIS(`iisreset`),處理序才會讀到新值。
- 開發時如果 User Secrets 沒生效,檢查順序建議為:
  1. `launchSettings.json`
  2. 系統與使用者環境變數
  3. 命令列參數
- 階層式名稱要用 `__`,例如 `ConnectionStrings__Default` 對應 `ConnectionStrings:Default`。
